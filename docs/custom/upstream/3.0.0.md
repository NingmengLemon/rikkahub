## 自动合并但需复核

两侧都改过、可以自动合并但仍需人工确认的 9 个文件：

- `AGENTS.md`：custom 改写了 speech 模块条目并追加 `## Custom branch`，上游改写了 Conversation 段落并加入 spotless 命令，hunk 不重叠会静默合并，最需要人工确认
- `app/build.gradle.kts`：C2 删的 `firebase.analytics` 与上游的版本号 bump、baselineprofile 块并存
- `di/AppModule.kt`、`di/ViewModelModule.kt`：C1 与 C5 的绑定删除对上游重构
- `ui/components/ai/ChatInput.kt`、`ui/components/ai/FilesPicker.kt`、`ui/pages/chat/ChatDrawer.kt`、`ui/pages/chat/ChatPage.kt`、`ui/pages/setting/SettingProviderDetailPage.kt`：需要确认我们的删除部位在上游改版后仍然成立

## 不冲突的利好

- 上游对 `speech/` 模块零改动，C5 删掉的 32 个文件不会与上游相撞。语音新功能只落在 app 模块
- `DefaultProviders.kt` 与 `RecommendedProviders.kt` 上游没碰，C3 不受影响
- 上游仍在使用 `firebase.analytics`，我们的删除在 `app/build.gradle.kts` 里可自动合并

## 需要单独验证

数据库迁移 `30 → 31` 会跑在现有数据上，这是 custom 分支范围内第一次真正改动 Room schema（上游此前已有多个迁移）。合并后要用旧数据实测升级路径，不能只看编译通过。

## 建议的合并顺序

先 `git rm` 那 6 个文件，再处理 7 个 `strings.xml`，最后手工过 4 个 Kotlin 文件。这样 `git diff` 里的噪声最少，逐项复核时不容易漏。
